# Reversible JPEG XL archives

The optional `archive` feature writes a standard JPEG XL container with JPEG bitstream reconstruction data. Before returning an archive, PixMinima independently decodes it and compares every byte with the original JPEG. A successful reconstruction includes entropy coding, metadata, comments, padding and scan order. The application chooses whether to keep an archive larger than its source.

## Supported inputs and limits

Archiving accepts a single 8-bit grayscale or three-component Huffman-coded JPEG with an end-of-image marker and no trailing attachment. This covers baseline and progressive inputs. MPF, APP11, unsupported layouts and failed round trips return an error. Restoration accepts an archival JXL with one complete codestream or an ordered series of codestream fragments and a JPEG reconstruction box. A regular JPEG XL image cannot recover a previous JPEG bitstream without reconstruction data.

The library bounds files and restored JPEGs to 64 MiB, dimensions to 20 million pixels, JPEG metadata to 8 MiB, scans to 96, JPEG markers to 8,192 and container boxes to 1,024. It measures expanded Brotli metadata before passing it to the reconstruction library. The decoder has a 512 MiB budget for its tracked allocations. The encoder and decoder also allocate memory outside that accounting, so this value is not a process-wide RAM ceiling.

## Dependency scope

The default build enables no dependencies in this crate. Both entry points report that the backend is disabled. Enabling `archive` selects three Rust dependencies with pinned versions.

| Dependency | Purpose | Licence |
| --- | --- | --- |
| [jixel 0.5.13](https://crates.io/crates/jixel/0.5.13) | JPEG-to-JXL encoding | BSD-3-Clause or Apache-2.0 |
| [zenjxl-decoder 0.3.10](https://crates.io/crates/zenjxl-decoder/0.3.10) | Independent JPEG reconstruction | BSD-3-Clause |
| [brotli-decompressor 5.0.3](https://crates.io/crates/brotli-decompressor/5.0.3) | Expanded metadata limits | BSD-3-Clause or MIT |

PixMinima's source forbids unsafe code. The optional JPEG XL dependency graph **uses unsafe Rust** with both codecs' default features disabled and only the decoder's `jpeg` feature enabled. A compiler run for `aarch64-apple-darwin` with Rust 1.100.0 and `--force-warn unsafe-code` reported 52 diagnostics in the encoder, 300 in `safe_unaligned_simd` and 279 in `bytemuck`, among other crates. Counts describe the code compiled on that target. A build advertised as requiring safe Rust throughout its codec dependencies must keep this feature disabled.

## Functional verification

Run `cargo test -p pixminima-jxl --features archive` for byte-exact baseline and progressive reconstruction, independently encoded data, malformed or ineligible inputs, and expanded metadata limits. The progressive test fixture is a generated 24 × 16 RGB pattern encoded by libjpeg-turbo 3.2.1 at quality 85, with a COM segment. Its reference JXL was produced by cjxl 0.13.0 with JPEG reconstruction enabled. The reference JXL decoder djxl 0.13.0 also reconstructed the original Hubble Deep Field, retina and rocket JPEG files byte-for-byte from archives written by PixMinima. The reverse check used archives generated by cjxl and reconstructed by PixMinima. These external programs are only verification tools.
